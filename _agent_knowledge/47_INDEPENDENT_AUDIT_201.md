# Независимый аудит0.20.1 ·20 октября2026

Основание: пользователь поручил полностью проверить целостность приложения, связи блоков и мёртвый код, исправить проблемы, обновить знания, собрать новый APK и сразу опубликовать всё на GitHub. Это разрешает commit/push/PR/обычное слияние/tag/release данной итерации.

## Выявленные проблемы и исправления

1. AddToListViewModel и ShopCardViewModel не фиксировали поколение базы. После полного восстановления прежний экран мог обратиться к другому объекту с тем же числовым ID. Оба окна сохраняют sessionGeneration при создании и выполняют запись через ProductEditorTransactions.inGeneration. Ошибка показывается в текущем экране; успех/навигация не отправляются. Повторное открытие после восстановления работает обычно.
2. favoriteGroup/favoriteDepartmentType вычисляли новый порядок даже для повторного флага. Импорт с допустимым Int.MAX_VALUE блокировал повторное избрание и добавление новой группы. Теперь повтор идемпотентен; при необходимости порядок уплотняется с сохранением текущей последовательности, затем новая группа добавляется в конец. ID, стили, displayOrder, местные отделы и покупки сохраняются.
3. В production оставались команды отменённого текстового редактирования корзины и прошлые способы управления карточками. Удалены вместе с тестовым макетом несуществующего UI, не переносились обратно в production или скрытые совместимые заглушки.
4. В массовых командах и согласовании raw-черновиков оставалась запись отдельных групп по точкам, уже удалённая из UI0.19. Удалены branchId и соответствующие ветви; общая группа применяется ко всему магазину, старые исключения остальных магазинов сохраняются.
5. Удалены прежние ручные перестановки обычных групп/алфавитная запись их displayOrder. Полные списки всегда строятся через alphabetical; ручные команды работают для избранного. Получатели/единицы сохраняют согласованную прежнюю логику.
