# Ввод, фотографии и варианты товара ·0.29

Запрос25 октября2026 из приложенного пользователем текста: сначала общие очистка/голос в полях, минус в подборе и единый цветовой редактор; затем варианты товара и фотографии.

Действующий контракт: один видимый товар семейства в каталоге; существующая запись становится первым вариантом без изменения ID. Варианты имеют собственные фотографии (до5, порядок/подписи), единицу/количество, формат, цены, заметки и магазины/точки. Название товара, группа, получатель, избранность и акцент общие. Приоритет и доступность вариантов задаются отдельно для каждого города; ручной выбор по умолчанию разовый, опциональная настройка запоминает его первым для текущего города. Покупка хранит фактический ID выбранного варианта; копирование списка сохраняет выбор. Просмотр карточки и свайпы сами по себе не меняют приоритет.

Новые связи не угадываются по имени. Старые фото/ссылки/покупки сохраняются миграцией; полный ZIP должен переносить все новые данные и все фото. Удаление варианта не должно незаметно удалять покупки; применяются прежние правила сохранения позиций отдельных списков. Старые версии копий читаются с одним вариантом и одним фото.

Состояние реализации и фактические проверки дополняются по завершении. Результаты0.28 не являются проверкой0.29.

## Реализованная модель

Room26: `product_variants` связывает реальные Product ID с одним familyId; существующий ID остаётся корнем и первым вариантом. `product_variant_cities` хранит доступность/порядок по городу. `product_photos` содержит до5 URI и подписей в позициях0–4. Схемы25 и старше сохраняются; миграция25→26 переносит прежнее photoUri в фото0, не меняя товары/покупки/ссылки.

ProductDao.getAll скрывает дочерние варианты только в каталоге. Для фактов покупок используется полный набор; отображаемое название дополняется меткой варианта без изменения канонического имени. Группа/получатель/избранное/акцент/название синхронизируются SQL-триггером даже для classifier/batch writers. Розничные ссылки/точки/цены/формат/единицы остаются независимыми. Мнимые «ссылки каталога» проецируют реальные ссылки вариантов на семейство исключительно для отображения, не записываются обратно как сырые ID.

Автоподбор учитывает разрешённые городские варианты и их порядок. При явно настроенном порядке города он первичен; без такой настройки предпочитается вариант с местной привязкой магазина. Явный выбор варианта в подборе сохраняет именно его ID. Городской редактор внутри вариантов не меняет глобальный город покупок. Смена глобального города переподбирает вариант только у регулярных некупленных автоматических покупок; планы отдельных списков и купленные факты сохраняются.

Обычное открытие карточки по существующему ID сохраняет эту страницу варианта; свайпы/стрелки меняют редактируемую страницу, а не покупку или приоритет. Для уже добавленной позиции есть явная команда «Заменить вариант». Она сверяет owner/updatedAt, сохраняет количество/единицу/ценовой план/заметки, меняет вариант и розничное назначение атомарно. Запоминание выбранного при добавлении/замене варианта выключено по умолчанию и ограничено текущим городом. Копирование списка сохраняет конкретный вариант. Переносимый список передаёт понятное название с меткой выбранного варианта; как и раньше, импорт такого списка создаёт самостоятельные временные позиции, а не копирует весь каталог/семейство.

Добавление/переименование варианта —явная команда сохранения. Создание сохраняет исходный товар, затем создаёт вариант с новой stableId, собственными пустыми фото/ссылками/ценой. Незавершённые параметры нескольких страниц держатся раздельно; в ручном режиме общий Save сохраняет их транзакционно, Back отбрасывает. В режиме autosave переход сохраняет предыдущую страницу и снимает её устаревший raw-черновик. Общие поля на последнем Save едины для всех страниц.

Удаление отдельного дополнительного варианта требует подтверждения. При имеющихся покупках его запись остаётся как временная самостоятельная позиция с понятным названием и всеми фото; существующие ID покупок не удаляются. Без покупок запись удаляется. Первый ID принадлежит семейству, поэтому отдельно не удаляется: его можно переименовать/отключить для города. Если удаление убрало единственный разрешённый вариант города, первый снова разрешается. Удаление всего товара сохраняет позиции отдельных списков прежним способом; все их фото и названия вариантов теперь переносятся и в эти временные копии.

## Общий ввод, подбор и оформление

AppTextField используется всеми редактируемыми обычными текстовыми полями. Непустой ввод показывает очистку; пустой текстовый ввод —системную speech activity. Числовые поля имеют очистку, dropdown readOnly сохраняют обычную стрелку. Голосовой результат меняет только черновик поля; отмена сохраняет прежний ввод. Не запрашивается запись микрофона приложением. Встроенный компактный числовой stepper сохраняет собственную механику.

Минус в подборе учитывает семейство, но читает реальные некупленные строки только текущего owner/listId. Уменьшается последняя строка шагом её фактического варианта/единицы; последняя единица удаляется, включая отдельные списки. Купленные и чужие списки не затрагиваются. Плашка добавленного должна иметь ту же область, что команда минуса.

В оформлении магазина включение подложки/товаров показывает одинаковый круг выбора цвета. Для товаров тот же AppearanceSheet дополнен переключателем «В тон подложки»: собственная палитра открывается после отключения. Черновик подпанели сначала применяется в оформление, затем в карточку. Фото: единая высота, горизонтальная прокрутка, первое —основное; нажатие открывает подпись, замену/камеру/удаление с подтверждением и позицию. Лимит5 проверяется writer, а не только disabled-кнопкой.

## Перенос и жизненный цикл

Полный ZIP24 переносит семейства, городские правила, подписи/порядок/файлы всех фото и переключатель запоминания. Старые версии читаются одним вариантом; новые поля в старом объявленном формате отвергаются. URI локального устройства в manifest не пишутся. До замены базы проверяются владельцы/FK/дубли/форматы и допустимые ссылки на медиа. Поколение базы продолжает защищать живые команды. MediaLifecycle удерживает фото базы и raw-черновиков; widget invalidation наблюдает новые таблицы. Окончательная проверка завершена; факты ниже.

## Проверенные уточнения

Подбор синхронно принимает выбранный Product ID и блокирует повторную запись до завершения разрешения варианта. Старое поколение базы отвергается до валидации формы. Сохранённый из дочерней карточки вариант не заменяется произвольно другим. Метка/минус учитывают owner/listId, выбранный магазин и предвыбранную точку; AUTO суммирует текущий список, NONE —только явное «Без магазина», EXPLICIT —текущий магазин/точку. Выбирается последняя изменённая строка, затем ID.

Городская панель кеширует правки каждого посещённого города. «Применить» записывает все города одной транзакцией, ошибка сохраняет панель и черновик. Запрещён набор без доступного варианта. Разовая временная позиция не становится каталожной молча: создание вариантов доступно после явного сохранения в каталоге. Замена уже добавленного варианта использует общий dropdown и монотонный updatedAt для CAS.

Обычный товар без metadata читается одним индексным lookup; варианты/правила читаются по familyId/cityId без полного сканирования каталога. Полный ZIP считает логические товары отдельно от вариантов, все отсутствующие фото попадают в preview. Файлы новых фото лежат в `variant_photos/`, старые первичные —в `photos/`; имена не конфликтуют даже при stableId с суффиксом. Отсутствующее фото требует явного маркера. Очистка файлов защищает все URI raw-черновика, включая восстановление после завершения процесса.

Автовыбор при явной точке сначала ищет разрешённый вариант, действительно доступный в этой точке, и лишь затем применяет обычные значения по умолчанию. Контекстный выбор не переставляет городской приоритет. Применение того же варианта не меняет покупку; при замене сохраняется явно выбранная точка, если новый вариант в ней доступен. Каталожные проекции магазинов/доступности исключают вариант, отключённый в городе данного магазина; сырые связи, другие города и уже добавленные покупки сохраняются. Изменения правил обновляют открытый подбор.

Чтение семейства выполняется согласованной транзакцией по индексам familyId/cityId. Панель замены наблюдает тот же поток вариантов, что городской редактор: загрузка, данные и ошибка представлены одним результатом. Названия вариантов уникальны по нормализованному значению; при первом создании учитывается ещё не материализованный «Основной вариант». Полный импорт с одинаковыми названиями внутри семейства отклоняется до записи.

Пустое числовое поле не резервирует место под отсутствующую кнопку. Подписи пары количество/единица компактны, проверена высота на узком экране. Ширина фотографий следует пропорциям при общей высоте160dp; ограничения ширины96–360dp сохраняют читаемые подписи и горизонтальную прокрутку.
