# Целевые списки · 0.15.0

## Локальная0.15.0 — целевые списки,19 октября2026

По прямому запросу пользователя добавлена вкладка «Списки», прежняя «Список» называется «Покупки». Первый пункт открывает текущую корзину; остальные — отдельные именованные списки для рецептов/событий/проектов. По умолчанию они скрыты из общей корзины. В настройках списка можно включить показ в «Покупках»: отображаются те же строки, без копирования, отметки и количества общие.

Быстрые позиции не требуют магазина или сохранения в каталоге; доступны количество/единица, ориентировочная цена за единицу, место текстом и заметка. Валидный ввод автосохраняется, Back завершает запись; ID черновика защищает от повторной вставки. Можно добавлять из базы с избранными/поиском и необязательным подбором магазина. Массовые отметки/возврат/удаление/перенос между списками выполняются атомарно и проверяют владельца. Удаление каталожной карточки сохраняет целевую покупку как временную. Изменение единицы каталога не меняет единицу и смысл цены целевого плана.

Текстовый экспорт v1 и JSON-файл не содержат локальных ID. Импорт текста/файла имеет предпросмотр, проверки и создаёт новый скрытый список с некупленными позициями. Незнакомые места сохраняются текстом без создания магазинов/слияния каталога. Полная ZIP11-копия сохраняет все списки, видимость, ID/состояния и скрытые покупки; Room15 с миграцией14→15 сохраняет прежнюю корзину с listId=null. Внешний вид/настройки виджета прежние; его данные учитывают видимость и текстовые места. Текст основной корзины остаётся временным сообщением без write API.

## Инварианты и границы

- Один владелец у строки: regular=null или goal ID. Показ в агрегате не создаёт копий. Merge никогда не объединяет разных владельцев, цены или места.
- Целевой список добавляет каталог по ссылке, быстрые/импортированные позиции — временные продукты. Каталог не показывает temporary. Одноимённая временная позиция не мешает создать постоянную карточку.
- Цель хранит собственную единицу, количество и плановую цену; изменение дефолта каталога не меняет смысл плана. Связи/доступность реальных магазинов обновляются существующим механизмом; текстовое место остаётся независимым.
- Удаление каталожного шаблона клонирует referenced goal purchase в temporary перед FK-cascade; регулярное прежнее поведение сохранено. Удаление списка удаляет только его строки и неиспользуемые temporary.
- Перенос меняет listId тех же строк без merge. Atomic owner checks исключают устаревший выбор; массовая команда основной корзины повторно проверяет текущую видимость.
- Дебаунс450мс, mutex, NonCancellable insert+ID propagation и draftStableId предотвращают двойную запись при Done/Back/пересоздании. Неверный ввод остаётся в редакторе/состоянии, не затирает сохранённые значения.
- Команды/автосохранение редакторов выполняются через withSession под общей ProductEditorTransactions блокировкой с поколением базы; SavedState сверяет непереносимую DatabaseRevision. Полное восстановление с повторно использованными числовыми ID не даёт старому черновику изменить новый список. Новое окно переноса также проверяет поколение, старый выбор места — текущую видимость.
- Текстовые импорт/экспорт отделены от основного временного текстового сообщения0.14.0. Лимиты1МиБ/1000 позиций, finite/range/6dp количества, строгий JSON/UTF8, ошибки до commit. Предпросмотр виртуализирован, показывает заметки/срочность; крупное сообщение в private cache, Bundle содержит токен.
- Portable v1 сохраняет порядок/повторы/количество/единицу/цену/место/заметку/статусы. Новый импорт скрыт и unchecked, urgent сохранён; catalogue/store IDs не переносятся. Полная копия ZIP11 сохраняет IDs/stable IDs/статусы/visibility точно.
- Room15 nullable FK ALTER14→15, без destructive migration; старые строки regular. Старые ZIP читаются с пустыми списками и nullable полями, downgrade smuggling отвергается.
- Виджет: прежние layout/settings; показываются только aggregate-visible IDs, CAS отвергает скрытые/изменённые строки; текстовые места разделяются корректно.
