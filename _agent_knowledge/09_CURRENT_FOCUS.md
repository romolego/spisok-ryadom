# 09_CURRENT_FOCUS

**Назначение:** держать текущий практический фокус проекта и помогать агенту не бежать вперёд по несвязанным направлениям.
**Когда читать:** перед определением следующей итерации и перед оценкой приоритета новой задачи.
**Когда обновлять:** если меняется ближайшая цель, следующий шаг, текущий приоритет или набор тем, которые пока нельзя трогать.

## Какая ближайшая цель проекта сейчас

По запросу пользователя от 2026-10-16 приоритет изменён: сначала проверка и стабилизация существующей реализации, затем города и ввод покупок списком. История состояния списка и подготовка RuStore больше не являются ближайшим шагом. Результаты: `15_AUDIT_2026-10-16.md`.

## Какой следующий шаг должен выполняться

1. Отдельная узкая итерация безопасного бэкапа/импорта: сохранение временных покупок, идентичности товаров и фотографий при ошибке.
2. Единые команды списка: русский поиск, дробные количества, единицы измерения, корректное слияние, назначение магазина, атомарные изменения.
3. Города и активный профиль по умолчанию без дублирования каталога; миграция существующих данных с сохранением ID.
4. Многострочный ввод с предпросмотром, сопоставлением похожих товаров и подтверждением пакетного добавления.

В этой итерации выполнен анализ; функциональные изменения ещё не реализованы. Предложенная в аудите схема профилей и поведение переноса существующего списка требуют уточнения до реализации.

## Какой текущий приоритет

Сохранность пользовательских данных и предсказуемая логика обычного списка. Все изменения пока только локально на текущем ПК. Не смешивать исправление восстановления данных, миграцию городов и новую страницу текстового ввода в один большой патч.

## Что сейчас нельзя трогать без отдельного решения

Сейчас нельзя без отдельного решения:
- тащить серверную часть;
- вводить параллельные текущие списки;
- расползаться в сложный UI и вторичную логику;
- тянуть задачи второй очереди раньше стабилизации первой итерации;
- пересматривать базовую концепцию приложения, уже подтверждённую первоисточниками.
