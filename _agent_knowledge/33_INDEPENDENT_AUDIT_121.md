# Повторный независимый аудит0.12.1

Дата:18–19 октября2026. Запрос: целостность, одинаковая логика, связи, исправление и пересборка. Проверка не ограничена последней функцией: предметные ограничения, живые покупки, raw drafts/recovery, DB/ZIP/media/cancellation, native UI и массовые операции. Домен, storage и UI рассмотрены независимо; исправления перекрёстно проверены.

## Воспроизведение и исправления

1. Старая raw карточка при recovery могла возвращать прежние магазин/порядок/доступность после успешного переноса, прежнюю единицу после rename; удалённые получатель/товарная группа блокировали recovery; разрешённый отрицательный ID группы мог воскресить удалённый type. Введена общая boundary canonical delta→raw drafts. Сохранён несвязанный текст/незавершённые значения, rename сохраняет identity. Empty subset и all-points отсутствие ключа различаются. Команда с ошибкой не меняет prefs.
2. Привязка магазина одним действием не разрешала ожидающую AUTO-покупку в отличие от массовой команды. Оба пути теперь разрешают только ожидающую AUTO; valid explicit/купленные не трогаются.
3. Преобразование продавца с адресами в рынок удаляло links до использования продуктового point priority. Снимок маршрута снимается до изменения, новые retailers получают точный продуктовый порядок, прежние physical IDs/покупки/поля сохраняются.
4. Отмена вызывающей coroutine непосредственно после SQLite commit восстановления могла удалить уже принадлежащие базе фото и оставить старые черновики/настройки. Коммит и финализация ownership/draft generation/preferences завершаются в NonCancellable под редакторским lock. Тест отменяет Job из native SQLite outer endTransaction.
5. Купленное одиночное меню предлагало срочность, хотя bulk её запрещал. Меню скрывает её; пользовательский VM вызывает атомарную repository проверку strictPending. Низкоуровневый legacy API исторической записи сохраняет совместимость, которую проверяет прежний concurrent-commands test.
6. Новый venue/department UI не имел того же выбора раздела, что physical headers. Общий tri-state выбирает полный раздел даже свёрнутый, пересечения отдел/рынок не дублируют строки. Activity recreation/Back проверены.
7. Mass add из каталога с несколькими адресами подставлял preferred address без возможности выбрать видимый другой адрес. Добавлен явный picker точки/по приоритету/без адреса. Initial empty BatchOptions больше не позволяет обойти picker быстрым нажатием: действия ждут все источники.
8. Пока открыт transfer sheet, widget может отметить выбранную строку купленной. Раньше фильтрация silently переносила остаток и UI сообщал успех. UI команды используют strictPending, в transaction до всех изменений отвергают устаревший набор. Старый mixed API сохраняет совместимость.
9. Пересоздание Activity теряло выбранные ID каталога, особенно при временном default-виде до загрузки сохранённой группировки. Общий direct Saver сохраняет режим, ID и последний загруженный scope; настоящий переход вида очищает выбор, промежуточная загрузка — сохраняет. Проверены общий каталог, вид по получателям, магазины и каталог магазина.
10. Сохранённый выбор каталога мог пережить переход между вкладками и full restore, который переиспользует числовые ID для других сущностей. DatabaseRevision хранит локальный UUID вне переносимых настроек и меняет его только после успешного full commit. Общий Saver привязан к revision, открытая batch-панель закрывается; содержимое покупок пересоздаёт все свои временные действия по revision. Метка переживает перезапуск процесса, не импортируется из копии. Нативный сценарий проходит Products/Stores→Shopping→Settings→ошибочный/успешный import→возврат с теми же ID и иным UUID товара.

Активная карточка также перечитывает external raw delta перед следующим вводом/записью и через listener: старое состояние живой ViewModel не может вернуть прежнюю единицу после переименования. Raw writes/finish/onCleared используют общий lock; несвязанные новые заметки, незавершённое количество и UI readmodel сохраняются.

При очистке/переименовании справочников raw recipient/group/unit/department, уже отличающиеся от прежнего canonical значения и остающиеся валидными, сохраняются. Удаление Ромы не очищает уже выбранную Злату, удаление «Молочки» не стирает новую черновую группу «Напитки». Явная массовая команда по затронутому полю по-прежнему имеет приоритет через applyBatch/reconcileBatch. Отдельный native сценарий доводит исправленный raw ввод до canonical сохранения.

Дополнительно общий nullable-return command boundary проверен на ровно одно исполнение, nested locks/транзакции и rollback — отдельными тестами. No-op массовое намерение согласуется прежним explicit applyBatch.
