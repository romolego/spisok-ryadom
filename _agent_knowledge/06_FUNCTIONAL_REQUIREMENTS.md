## Исторический запрос пользователя, 2026-10-16 — до реализации

1. Общий каталог товаров между городами: один и тот же товар не заводится заново после переезда.
2. Выбор текущего города. Магазины и автоматическое назначение покупки соответствуют выбранному городу.
3. В дальнейшем — контекст района/адреса проживания и массовое изменение предпочтений магазинов без редактирования каждого товара.
4. Отдельный многострочный ввод покупок как в блокноте: название, количество и единица; вставка списка целиком.
5. Сопоставление с существующим каталогом: точные и похожие названия, выбор варианта пользователем, новая или разовая позиция. До записи — проверка неоднозначностей.
6. Сначала устранить подтверждённые проблемы сохранения данных и обычного списка. Предложения до реализации сохранены в `15_AUDIT_2026-10-16.md`; фактическая реализация и последующие исправления описаны ниже и в 18.

## Реализованный объём 0.2.0, 17 октября 2026

Требования последнего расширенного запроса реализованы локально: общий каталог между городами, магазины активного города, единый автовыбор/явный выбор, нечёткое сопоставление на основных путях, многострочный черновик с проверкой перед корзиной, атомарные операции и полное резервирование.

Город — контекст назначения новых покупок, а не фильтр, скрывающий старые покупки. Явное действие переназначает только некупленные товары. Адресные профили проживания отложены по исходному запросу. Каталог не размножается между городами.

Сопоставление текста не подменяет похожее название без подтверждения. Новые позиции разовые по умолчанию, сохранение в каталоге выбирается на строке. ## Текущий список, группы и точки сети — 0.3.0

- Текст и корзина — два представления одних покупок. В тексте только некупленные. Количество, единицы, магазин и адрес можно менять; удаление строк показывается до сохранения. Сохранение не очищает текст и не дублирует покупки. Неоднозначное сопоставление требует решения, старый черновик не затирает свежую корзину.
- Несохранённый текст сохраняется. Купленное, заметки, комментарии, срочность и ID существующих покупок защищены. Поддержаны отмена последней записи и rollback всего изменения при ошибке любой строки.
- Состояния сворачивания помнятся независимо по группировке и стабильному ID, а не по названию или позиции. Заголовок свёрнутой группы остаётся доступен.
- Сеть/магазин города может иметь несколько адресов; порядок задаёт предпочтение. Товар может продаваться во всех или только выбранных точках сети. Автовыбор учитывает ограничения. Разные адреса одной сети не схлопываются одной покупкой.
- Из корзины можно перенести одну позицию, выбранные позиции или все некупленные магазина. Купленные не перемещаются. Можно выбрать другую сеть или адрес той же сети; при индивидуальном автовыборе точки разных товаров могут различаться. Ошибка одной строки откатывает перенос целиком.

## Рынок/павильоны и глобальный поиск нового товара — 0.4.0

Магазин-контейнер может представлять сеть, рынок или ТЦ, точки — адреса/павильоны. У точки свои заметка и фото (галерея/камера). Группировка содержимого следует явной доступности товара по точкам, а не догадке по названию; общие товары отдельной группой. При покупке из конкретной точки запись корзины назначается туда. Для уже существующих товаров пользователь задаёт точки в карточке товара; при новом товаре из магазина выбор расположен сразу под именем.

Новый товар ищет точные/нечёткие названия во всём каталоге между магазинами/городами. «Использовать» сохраняет прежний ID и информацию, связывает с текущим магазином и открывает его карточку. Похожие свежие/солёные варианты остаются разными. Точный одноимённый новый товар допускается только отдельным явным действием. Текущий магазин включается в сохранение даже при раннем нажатии до эмиссии списка магазинов.

Добавленные/выбранные/новые группы — одинаковые строки и отступы, уже добавленная строка disabled, названия нормализуются. Меню действий имеет непрозрачную поверхность, площадь FAB зарезервирована под списком. Заметки/фото точек включены в ZIP6 с поддержкой ZIP4/5.

## Место покупки и карточка товара0.6.1

- Блок корзины = физическое место покупки. Один адрес только у заголовка; два адреса одного продавца отображаются отдельно, со своими позициями/свёрнутостью/выбором/очисткой.
- Меню покупки отдельно меняет место текущей некупленной записи и добавляет новый магазин к общей карточке. Смена сохраняет ID, количество, единицы, срочность, заметки, комментарии и createdAt, не меняет каталог. Копирование связи сохраняет покупку целиком и прежние приоритеты/availability.
- При выборе нескольких покупок показываются общие доступные физические места; непривязанные магазины и чужой город исключены. Изменившаяся после открытия меню доступность проверяется заново до записи, весь пакет откатывается при ошибке.
- При добавлении из адресного блока сохраняется точная точка. Старое состояние «свёрнут магазин» наследуется каждым адресом, после явной правки адреса состояния независимы.
- Сеть необязательна. При пустом справочнике действие добавления сразу раскрывает inline-имя; при непустом доступны выбор и создание. Отмена не создаёт записей в БД.

Изменение количества/заметки не переназначает покупку, даже если её место изменилось после открытия редактора. Ручная перестановка адреса имеет приоритет над подъёмом срочного. Выбор места с длинным списком оставляет кнопку подтверждения доступной в коротком окне.

## Целостность0.12.1

Успешные внешние команды переноса/справочников/связей не отменяются последующим восстановлением старой карточки. Переименование общей группы сохраняет её ID даже для уже разрешённого отрицательного ID сырого черновика. Удалённые recipient/group/department/shop очищаются только в соответствующих raw ссылках; несвязанный ввод остаётся. Пустой выбранный subset не расширяет доступность, отсутствие ключа subset продолжает означать все точки. Сбой команды откатывает БД без изменения черновика.

Глобальная очистка справочника не заменяет другой уже выбранный валидный raw вариант тем же null, который получил canonical старый вариант. Новые recipient/group/unit/temporary department сохраняются до исправления незавершённого числа и последующего сохранения. Явное массовое назначение поля обновляет именно выбранный набор и согласует это намерение независимо от canonical no-op.

Живая карточка тоже согласуется с внешней правкой, а не только будущий recovery. Если пользователь после внешнего rename продолжает вводить заметку или закрывает Activity во время окончания команды, последняя raw запись сохраняет новую единицу и новый локальный текст. Недопустимое незавершённое количество сохраняется как ввод, canonical row не портится.

Полное восстановление сбрасывает прежнее выделение и открытые действия во всех представлениях, включая сохранённые между вкладками каталоги. Совпадающие ID новой базы не наследуют выбор прежних записей. Ошибочный импорт не меняет revision/выбор; постоянная локальная revision не переносится из резервной копии и переживает перезапуск.

Одиночная привязка магазина, как массовая, разрешает ожидающие AUTO-покупки; валидные явные и купленные не переносит. Срочность относится к некупленным и одинакова в одиночном/массовом действии. UI перенос проверяет, что весь выбранный набор ещё некуплен; если хоть одна строка изменилась, отклоняется до любых связей/приоритетов/покупок. Legacy repository mixed API по-прежнему может переносить только pending подмножество. В каталоге многоточечного магазина массовое добавление требует явной точки либо явного выбора режима по приоритету/без адреса.
