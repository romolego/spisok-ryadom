# Настройки, карточки и города ·0.28.0

Запрос23 октября2026: все настройки виджета в одной нижней панели; размер12–22 через dropdown. Справочники открываются по запросу в отдельных панелях, сброс внизу. В карточках единая звезда вместо checkbox; фото товара между звездой и палитрой, снимок ниже. Формат покупки до количества, смешанный формат разрешён явно. Для одной точки выбор доступности скрыт. Город покупок только в настройках, избранные товары/магазины обозначаются заголовком. Массовые магазины доступны через карандаш и поддерживают отделы, избранное, тип покупки и срочность.

Главная семантическая правка: город в карточке магазина выбирает локальный профиль адресов, а не переносит прежние точки. Городские профили имеют явную общую идентичность; старые профили автоматически по имени не склеиваются. Отмена не сохраняет адреса, Save сохраняет затронутые города атомарно. Прежние товары/связи/покупки сохраняются, автоматический выбор использует только активный город. Реализация и результаты подтверждены ниже.

Городские адреса сохраняются отдельными ShopEntity с cityGroupKey, не смешанным с networkId. При явном добавлении адресов нового города наследуются ссылки каталога этого магазина с привязкой к местным отделам; старые связи и физические ID не переносятся. Пустой новый городской раздел существующего магазина не создаёт профиль. Старые одинаковые имена не склеиваются.

Смена города покупок через настройки автоматически подбирает местные магазины для некупленных регулярных строк. При отсутствии местной привязки строка остаётся без магазина и ждёт его в новом городе. Купленные строки, отдельные списки, явное «Без магазина» и свободные текстовые места не переназначаются. Низкоуровневый LocationRepository.select используется восстановлением/стендом без скрытого изменения снимка; пользовательский путь —ShoppingListRepository.changeShoppingCity. Фото/бренды, количества, владение строками и старые адреса сохраняются.

Идентичность городских профилей защищена валидатором ZIP, атомарным writer и SQL-триггерами уникальности непустого cityGroupKey+cityId. Пустые старые ключи остаются независимыми. Отделы семейства без явной сети синхронизируются по cityGroupKey; с явной сетью действует прежний общий маршрут отделов сети. При физическом переносе ТЦ в город с уже готовым профилем того же магазина операция отклоняется до записи, чтобы не создать двойной городской профиль. Старые миграции вызывают установку новых триггеров только при наличии колонки.

Общий черновик отделов и переименования уже существующей сети применяется при каждом переходе между городскими разделами. Поэтому второй городской снимок не возвращает прежний порядок/состав или имя сети при общем Save. Локальные адреса и настройки остаются в своих разделах. Для сопоставления сохранённых отделов используются глобальные typeId и локальные ID размещений; новые временные строки не подменяют существующие.
