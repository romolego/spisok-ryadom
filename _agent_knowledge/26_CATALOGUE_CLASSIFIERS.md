## Покрытие запроса

1. Каталог по магазинам и содержимое магазина группируются по местным отделам, затем имени. Избранное выше внутри отдела. Контекст кнопки/количества — показанный магазин; покупка того же товара в другом магазине не подменяет его controls.
2. Успешное добавление покупки закрывает форму, в том числе для нового товара с новым магазином. Ошибка оставляет ввод на месте.
3. Отдел меньше/тусклее/смещён относительно магазина. У рынков/ТЦ общий заголовок поездки, ниже павильоны/магазины, затем их отделы. Свёрнутость поездки сохраняется. Физические ID/покупки не дублируются.
4. Общие группы магазинов имеют ручной порядок. Все четыре справочника настроек используют одинаковые стрелки и подтверждаемый алфавитный сброс; плюс и сброс скрыты вне правок. Локальный маршрут магазина тоже подтверждает сброс. Управление порядком убрано из карточки товара.
5. Группы/получатели могут иметь цвет и один из28 встроенных Material Icons; товар — избранное/цвет. Отметки необязательны, передаются через backup. Фильтр избранного запоминается. Лицензия Apache2.0 включена в APK.
6. Глобальная группа создаётся без привязок. Выбор общей группы в товаре создаёт только локальное размещение нужного магазина в общей транзакции сохранения карточки.
7. Сохранение карточки обновляет некупленные отдел/стандартную единицу на месте; собственная единица/количество/заметки/срочность/ID/дата создания сохраняются. Купленная история не переписывается. Удалённое доступное место заменяется доступным в прежнем городе. Только изменение количества/заметки и копирование связи не двигают покупки. Миграция исправляет прежние пустые единицы и устаревшие отделы некупленного.
8. Выборы справочников поддерживают очистку/создание из контекста: группы, получатели, магазины, сети, комплексы, города, адреса текстового review. «Без магазина» не становится первым магазином. Адрес может быть явно не выбран, в отличие от автоматического подбора. У города магазина обязательный FK сохраняется, нейтральный вариант явно «Текущий город». Редактируемая единица допускает пустое/новое значение.

## Границы и совместимость

Старый неопределённый контейнер магазина переводится в рынок/ТЦ явным действием карточки; имя не используется для угадывания. Купленные покупки сохраняют исторические единицы/отделы. Изменение стандартной единицы не выполняет математическое преобразование количества. Непустая отличающаяся единица покупки считается явной. Несохранённые карточки по-прежнему в ViewModel; постоянный текстовый черновик и сохранённые данные на диске. Только некупленное в тексте. FPS/OEM IME/реальная камера на телефоне не измерены.

## Knowledge review

Проверены01/02/03/05/06/07/08/09/10/11/12/13/14/24/25. Обновлены01/02/05/06/07/08/09/11/13/14/README, добавлен26;10/12 сохраняют прежние правила. Прежние отчёты и поставки не заменяются.

Ненастроенное автоматическое назначение хранит awaitingShopCityId: при последующей настройке карточки выбирает магазин первоначального города. Явное «Без магазина» хранит null и не назначается автоматически. Такие разные намерения не сливаются в одну покупку. Для старых записей неизвестное намерение не угадывается; nullable hint мигрирует нейтральным. Это контекст подбора, не владение города покупкой; после явного переноса очищается.

explicitNoShop отдельно хранит явный выбор, чтобы не путать его с нейтральным старым NULL. Старые записи могут объединяться с новым автоматическим добавлением при однозначном городе и совместимых фактах/единицах; разные города и явное «Без магазина» с автоматическим назначением не сливаются.

Основной выбор группы магазина показывает только его локальные размещения. Общие ещё не назначенные группы открываются отдельным inline-выбором после «Добавить группу»; из него также создаётся новая. Наличие в общем справочнике не изображается готовой привязкой магазина. Прежние пустые размещения не удаляются угадыванием: они могут быть намеренно настроенным маршрутом.
