# Независимый аудит приложения · 0.15.1

## Независимый аудит0.15.1 —19 октября2026

По повторному запросу пользователя проверено приложение с акцентом на целевые списки, их владельцев/видимость, общий каталог и корзину, импорт/экспорт и полное восстановление. Работу разделили на независимые проверки домена, обмена/backup и UI с перекрёстным чтением исправлений. Сохранена единая модель покупки: один владелец, showInPurchases без копий.

Исправлены потеря последнего валидного ввода при внешней навигации/уходе в фон, блокировка устаревшего редактора, скрытый комментарий, откат свежих полей несвязанной правкой, потеря быстрых прибавлений, изменение единиц ценового плана через справочник, устаревшие команды каталога/агрегата и очередь команд после восстановления. Введены атомарная маска изменённых полей и единые десятичные суммы/округление. Последняя единица целевой позиции сохраняется одинаково в её списке и в агрегате.

Portable v1 читается как раньше; отдельный комментарий сохраняется без слияния с заметкой через v2 текста/JSON (экспорт выбирает v2 только при непустом комментарии). Неверная версия не принимается молча. Чеклисты [ ]/[x] распознаются как текст; границы чисел проверяются до Double. ZIP11 строже проверяет новые поля и UTF-8 до commit. Большие сообщения отправляются UTF-8.txt с read grant, короткие — текстом; у общего и целевого экранов один helper.

## Подтверждённые дефекты и исправления

- UI teardown отменял450мс debounce до записи. ON_STOP/onCleared завершают валидную запись под теми же mutex/generation; ID черновика сохраняет идемпотентность. Пустой именем, но заполненный другими полями редактор больше не закрывается как пустой.
- Перемещённая/удалённая позиция могла навсегда удерживать редактор, особенно при невалидном вводе. Fresh owner check до локальной валидации закрывает только устаревший редактор, без пересоздания покупки.
- Regular comment сохранялся в БД, но скрывался в целевом UI; экспорт объединял note+comment и мог превысить10к. Теперь это отдельные поля в редакторе, SavedState, DTO и portable v2. Старый v1 остаётся читаемым.
- Редактор отправлял весь старый снимок: правка заметки могла вернуть прежнее количество/цену/магазин. GoalItemField mask меняет только затронутые поля, читая остальные в той же Room-транзакции. PLACE является цельным местом покупки; явная правка места сохраняет прежний способ detached text.
- Быстрый +/- вычислялся по прежнему UI row. Новая транзакционная delta-команда читает актуальную строку, проверяет владельца и меняет только количество. Последняя целевая единица не удаляется из агрегата кнопкой минус; удаление остаётся явным действием.
- Изменение словаря единиц затрагивало независимые целевые цены. Rename/delete меняет defaults каталога и regular pending; единицы целевых покупок и их цена сохраняются.
- Устаревшие одиночные команды агрегата затрагивали скрытые планы; устаревшие controls каталога — перенесённые в цель строки. strictVisible/regularOnly проверяются атомарно с записью. Команды основной корзины/каталога/массовых действий фиксируют generation перед запуском и под общим lock отвергают очередь прежней базы.
- Целевой UI группировал текстовые места по готовой подписи: разные name/address с одинаковым отображением сливались. Ключ теперь строится из исходной пары, реальный shop/branch остаётся отдельной идентичностью.
- Денежные подписи main/goal использовали разное округление. PurchaseMoney использует десятичное умножение и HALF_UP до копеек; итог суммирует неокруглённые amounts, остаток считается по pending отдельно, без вычитания больших Double.
- Portable parser принимал число после округления Double и ошибочно считал начальный [ ] JSON. BigDecimal-проверка до преобразования защищает6dp/range; checklist распознаётся отдельно.
- ZIP11 мог приводить дробный/string listId к Long, отсутствие метаданных — к null, повреждённый UTF-8 — к символам замены. Новые поля/типы/целочисленная версия и декодирование проверяются до восстановления; повреждённый файл оставляет базу и настройки прежними.
- Большое EXTRA_TEXT могло превысить Android Binder. Общий MessageShareIntent оставляет до32768 UTF16 chars текстом, больше — immutable UTF-8.txt через узкий cache FileProvider. Файл не перезаписывается следующим chooser, cleanup7дней. Goal portable input/export limit1МиБ сохранён; общий текст не становится write API.
