## Что реализовано

- Версия приложения 0.2.0 (2), Room schema 8. Миграции 1→8 без destructive fallback; схема 8 экспортируется в `app/schemas`.
- Общий каталог товаров и отдельные магазины по городам. Старые магазины получают город «Мой город», который пользователь переименовывает. Новый город можно добавить с любого основного экрана.
- Новые покупки подбирают магазин только текущего города. Автовыбор использует порядок привязок товара среди магазинов этого города; при равных приоритетах учитывается порядок магазинов. Явный выбор и «Без магазина» имеют однозначную семантику во всех точках добавления.
- Смена города сохраняет уже заполненную корзину. Непокупленные позиции другого города видны с названием города; их можно явно переназначить. Купленные не переносятся.
- Один общий текущий список. Адресные профили проживания и несколько независимых списков не добавлялись.
- Общий локальный нечёткий поиск: русский регистр, ё/е, пробелы, точное совпадение, начало/часть названия и опечатки; сортировка по релевантности. Используется в каталоге, добавлении, подборе товара для магазина и разборе текста. Это Kotlin `FuzzySearch`, без JavaScript Fuse и без сетевого ИИ.
- «Ввести списком»: сохраняемый текстовый черновик, до 200 непустых строк, десятичная запятая/точка, проверка кандидатов, новых/разовых товаров, количества, единиц и магазина. Неоднозначные похожие названия требуют выбора. Добавление всего пакета атомарно, поддерживается отмена до последующих изменений покупок.
- Совместимые покупки объединяются по товару, нормализованной единице и магазину. Разные единицы/магазины остаются разными строками. Повторные новые названия внутри одного пакета объединяются. Купленные строки не поглощают новые покупки.
- Изменения количества атомарны, двойное сохранение защищено. Дробные количества не повышаются молча до единицы. Невалидное количество требует исправления.
- Привязки магазинов и отделы в карточках являются черновиками до «Сохранить»; сохранение полей и связей в одной транзакции. Удаление товара выполняется до очистки его старого фото.
- Разовые товары исключены из каталога, удаляются после удаления последней покупки. Их можно явно сохранить в каталоге через карточку.
- Полная резервная копия ZIP v4 включает каталог, разовые товары, корзину, города, связи, фото и настройки. Фото читаются/пишутся последовательно в фоне. Проверка архива и подготовка фото происходят до изменения БД; неудачный импорт откатывается и оставляет старые фото.
- Старые JSON v1–3 импортируются как слияние каталога с переназначением ID. Числовое совпадение ID другой базы не подменяет товар текущей покупки. Старые покупки сохраняются.
- Фото уменьшаются до 1600 пикселей с учётом EXIF, превью до 800. Настройки и каталог используют ленивые списки, группировка/нечёткий поиск вынесены с основного потока, ключи строк основаны на ID, а не совпадающих названиях. Автоматическое заполнение демонстрационными товарами отключено.
