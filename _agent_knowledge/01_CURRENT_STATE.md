## Что уже реализовано в коде

### Быстрое редактирование записи текущего списка
- Основное взаимодействие с записью списка — это работа с текущей покупкой, а не с карточкой товара.
- Короткий тап по основной зоне карточки записи (название товара, детали, заметка) открывает диалог редактирования записи. Чекбокс «куплено» и иконка срочности обрабатываются отдельно и не конфликтуют с общим тапом.
- Справа от каждой записи расположен встроенный компактный блок управления количеством: кнопка «−», текущее количество с единицей измерения, кнопка «+». Кнопки позволяют быстро изменить количество прямо в карточке, без открытия диалога.
- Шаг изменения количества через «−»/«+» определяется полем `defaultQuantity` карточки товара: если оно задано и больше нуля, то используется как шаг; иначе шаг равен 1. Например, при `defaultQuantity = 100` значения идут как 100, 200, 300. Кнопка «−» недоступна при количестве ≤ шага и для купленных позиций. Кнопка «+» недоступна для купленных позиций.
- Диалог EditEntryDialog остаётся как дополнительный сценарий для ручного ввода количества, назначения магазина (с приоритетом связанных магазинов), добавления заметки и одноразового комментария к покупке.
- Количество и единица измерения в записи текущего списка (ShoppingListEntryEntity.quantity/unit) независимы от значений по умолчанию в карточке товара (ProductEntity.defaultQuantity/defaultUnit).
- Значения по умолчанию из карточки товара используются только как стартовая подстановка при добавлении товара в текущий список.
- Долгое нажатие на запись открывает контекстное меню с расширенными действиями в порядке: сделать срочным (первый), перенести в магазин (второй), открыть карточку товара (третий, не акцентирован), удалить запись (после разделителя).
- Удаление записи из контекстного меню требует подтверждения через ConfirmDialog.
- Удаление записи и переход к карточке товара убраны из основного UI записи и доступны только через контекстное меню (long press).
- Диалог редактирования записи при сохранении гарантирует минимальное количество 1.0 (пустое или нулевое поле нормализуется до 1.0).
- Загрузка связанных магазинов в диалогах редактирования и переноса переведена в `LaunchedEffect`, чтобы исключить запуск корутин во время композиции и гонки состояния.

### Сводка списка и стабильность интерфейса
- Под переключателем режимов показывается компактная сводка: общее количество позиций и количество купленных (если есть).
- Кнопки перемещения магазинных блоков (вверх/вниз) в режиме «по магазинам» всегда отрисовываются для всех магазинов с groupId, но недоступные кнопки показываются приглушёнными и неактивными — это предотвращает скачки макета при смене позиций.
- Во всех местах приложения, где есть ручное перемещение элементов вверх/вниз (текущий список — блоки магазинов, список магазинов, карточка товара — привязки магазинов, карточка магазина — группы магазина, служебные настройки — получатели и товарные группы), экран автоматически подстраивается при перемещении, чтобы перемещаемый элемент оставался в фокусе пользователя. Для LazyColumn-экранов используется animateScrollToItem, для verticalScroll-экранов — animateScrollBy.

### Переключаемые представления текущего списка
- Текущий список поддерживает 4 режима представления: по магазинам, по группам товаров, по получателям, общий без группировки.
- Переключение через горизонтальный ряд FilterChip на экране списка.
- Выбранный режим сохраняется в SharedPreferences (`shopping_list_prefs`) и восстанавливается при повторном открытии.
- Внутри каждого режима работает единая сортировка: срочные некупленные → обычные некупленные → купленные; при равном статусе и срочности товары идут по алфавиту (productName.lowercase()).
- Фильтр «Только срочные» теперь показывает только активные срочные позиции (`isUrgent && !isBought`) без подмешивания купленных.
- Очистка купленных по группе доступна только в режиме «по магазинам» (canClearBought).
- В режимах «по группам», «по получателям» и «все» в карточке записи показывается название магазина как контекстная информация.
- Модель данных ShopGroup обобщена до EntryGroup, ShoppingListEntryUi расширена полями groupName и recipientName.
- ViewModel использует ClassifierRepository для загрузки групп и получателей.

### Порядок магазинов и сворачивание блоков в текущем списке
- В режиме «по магазинам» пользователь может менять порядок магазинных блоков кнопками вверх/вниз в заголовке каждого магазина.
- Новый порядок сохраняется через поле displayOrder сущности ShopEntity в Room-базе и не сбрасывается при перезапуске.
- Блок «Без магазина» всегда отображается последним и не участвует в перестановке.
- В режиме «по магазинам» каждый магазинный блок можно свернуть/развернуть кликом по заголовку.
- В свёрнутом виде остаётся заголовок магазина с иконкой состояния (стрелка) и счётчиком позиций (активные / всего).
- Состояние сворачивания сохраняется в SharedPreferences (`shopping_list_prefs`) и восстанавливается при повторном открытии.
- Сворачивание и перестановка работают только в режиме «по магазинам» и не затрагивают другие представления.
- Добавлен управляемый переключатель «Срочные в свёрнутых»: по умолчанию выключен, при включении в свёрнутом блоке показываются только срочные некупленные позиции.
- Настройка «Срочные в свёрнутых» сохраняется в `shopping_list_prefs` и восстанавливается после перезапуска.

### Быстрое добавление позиции в текущий список
- Кнопка «+» на главной странице текущего списка покупок открывает отдельный экран «Добавить в список» (AddToListScreen), а не переводит во вкладку товаров.
- На экране пользователь выбирает магазин (по умолчанию «Без магазина»), ищет существующий товар из базы или вводит новый.
- Для нового товара доступен флажок «Сохранить в базе товаров». Стартовое состояние флажка определяется глобальной настройкой в служебных настройках (по умолчанию включён). При снятом флажке товар создаётся как временный (isTemporary=true) и не появляется в общем справочнике товаров.
- Позиции без выбранного магазина попадают в блок «Без магазина» в текущем списке.
- После успешного добавления экран автоматически закрывается (`shouldNavigateBack = true` → `onNavigateBack()`); пользователь возвращается на главный список покупок без ручного действия. Возврат через стрелку в TopAppBar остаётся доступен для отмены без добавления.

## Что уже зафиксировано по концепции приложения

Из первоисточников уже подтверждены:
- проект называется «Список рядом»;
- это локальное Android-приложение;
- в первой версии используется один общий текущий список;
- основа модели строится вокруг карточек товаров, магазинов, отделов магазинов, связи товара с магазином, пользовательских групп и получателей;
- данные хранятся локально;
- выпуск планируется в RuStore;
- проект развивается строго итерационно.
