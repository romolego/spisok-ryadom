# Общий адрес рынка / ТЦ и редакторы точек ·0.23

Запрос21 октября 2026: произвольный порядок точек сети, один почтовый адрес ТЦ/рынка, отдельные сведения и фото продавца внутри, единые редакторы и аудит на личном ZIP16. Ветка codex/venue-addresses-0.23.0-2026-10-21. Room20/ZIP17, code31.

## Модель места

- Shop — профиль магазина в городе. Network — необязательная сеть. Venue — рынок или ТЦ. Эти связи независимы: один профиль содержит уличные точки и точки разных ТЦ.
- Venue.address — единственный общий почтовый адрес. Он может быть ещё не указан; номер павильона нельзя выдавать за почтовый адрес. Выбранный ТЦ немедленно показывает свой адрес, повторного ввода нет. Изменение адреса/названия Venue обновляет все использующие его представления.
- ShopBranch.address — почтовый адрес самостоятельной точки (неизвестный допустим при наличии label); для точки с venueId хранится пустым. ShopBranch.label — необязательные номер павильона, этаж, вход либо название точки. Фото точки остаётся отдельным от нового Venue.photoUri.
- Shop.address сохранён как совместимый кэш первого адреса; UI использует PlaceLabels и реальные точки. Репозиторий синхронизирует кэш при сохранении/изменении/удалении Venue. Не использовать этот кэш как адрес нового рынка при преобразовании.
- Удаление Venue сохраняет точки/сеть/товары/покупки; перед снятием ссылки копируется актуальный общий адрес. Условное описание точки остаётся label. Если общего адреса не было, он остаётся пустым, а имя Venue сохраняется как обозначение; нельзя подставлять его в почтовый адрес.

## Порядок

BranchesEditor показывает компактные строки и постоянно доступные стрелки. OutletLocations.move работает по ID в текущем списке, уплотняет displayOrder; новый отрицательный ID тоже можно поднять первым. Обычный Column заменяет анимированное размещение больших редактируемых форм. В хранилище сохраняется фактический порядок списка; ID не меняются. AssignmentCatalogue уже выбирал displayOrder перед id, этот контракт сохранён. Отдельный приоритет точки конкретного товара по-прежнему выше общего; существующие покупки остаются фактами, их не перемещают только ради нового приоритета.

## Единый редактор

PlaceEditorDialog — общее полноэкранное модальное окно: назад слева, «Сохранить» справа вверху, прокручивается только тело, учтены системные отступы и клавиатура. Используется для точки и для Venue. Старое inline-редактирование VenueHeading и строковый venueNames-черновик удалены. Новый Venue черновик содержит все поля; отдельного пути создания «только по имени» в карточке больше нет.

В карточке магазина изменения точек и вложенные изменения Venue относятся к черновику магазина и фиксируются одной транзакцией по общей кнопке Save магазина. Отмена/назад всей карточки не записывает их. Открытый из списка магазинов VenueEditor сохраняет собственную сущность непосредственно; ошибка оставляет редактор открытым. Оба пути проверяют поколение базы. Вложенные отрицательные Venue ID разрешаются в настоящие в транзакции, не записываются в FK.

OutletDraftSaver и rememberSaveable хранят незавершённую форму точки, её открытое состояние и выбранный редактор Venue при пересоздании Compose. Фотографии используют прежний защищённый асинхронный импорт/камеру; для мест выбран компактный режим без постоянных текстовых кнопок. Удаление фото требует подтверждения. Фото ТЦ видно отдельно от фото конкретной точки.

## Единые подписи

PlaceLabels.address/detail/place/branch разделяют почтовый адрес и обозначение. Полное место содержит контекст Venue, продавца, обозначение и общий адрес без одинаковых строк. Под общим заголовком ТЦ в покупках и виджете почтовый адрес показывается один раз; вложенный магазин показывает собственное обозначение. Перенос, добавление места, целевые планы/экспорт и простой текст используют те же текущие адреса. Макет/настройки виджета не перерабатываются.

## Миграции и медиа

MIGRATION_19_20 добавляет label и Venue.photoUri, снимает прежний уникальный индекс shopId/address: пустые адреса точек разных Venue допустимы. Репозиторий/валидация backup проверяют составной ключ места; новые SQLite-триггеры защищают от точных повторов, включая NULL venue. При промежуточной старой миграции триггеры label устанавливаются только если колонка уже есть.

OutletLocations.migrate — общий нормализатор Room и старых ZIP: копию адреса Venue или имени продавца убирает из адреса точки; другое прежнее содержимое сохраняет как label. Неоднозначные совпадения сохраняют все ID и различимые обозначения, без слияния точек. Все прежние миграции, схемы и читатели локальных отделов сохраняются. Старый неиспользуемый BranchAvailabilityEditor удалён; актуальный ProductOutletOptions остаётся.

ZIP17 хранит label и отдельные venue_photos/<id>.jpg. Старые поддерживаемые копии читаются, неизвестные будущие и неверные типы отклоняются до замены базы. Фото Venue участвуют в export leases, импорте staging, удержании MediaLifecycle, cleanup, recovery и полном ResetRepository. Пути локальных файлов в manifest не экспортируются. Перенос отдельного целевого плана не расширяет свой формат фотографиями локального каталога.

## Смена города сети с несколькими ТЦ

После полного набора 1089 отдельный пограничный тест воспроизвёл на API28/35 временный конфликт составных ключей: отвязка двух Venue с пустыми address/label превращала их в одинаковые уличные точки до записи нового черновика.
