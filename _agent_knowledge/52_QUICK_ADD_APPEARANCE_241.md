# Быстрое добавление, оформление магазина и общие отделы ·0.24.1

Запрос пользователя после проверки0.24: выбор единиц в быстром добавлении, отсутствие скачков при вводе имени, компактное оформление магазина в модальном окне и единый порядок отделов для всех точек сети. Room21/ZIP18 сохраняются; новых полей и миграций нет. Итоговые проверки и APK —01.

## Быстрое добавление

AddToListViewModel получает живой справочник единиц через ClassifierRepository. Поля количества/единицы используют тот же QuantityUnitInputWithSuggestions, что карточка товара: подходящие единицы наверху, остальные не скрываются, свободный ввод остаётся разрешённым.

Текст поля меняется сразу. Поиск выполняется после паузы300мс; очередной ввод отменяет ожидание предыдущего запроса. Во время ожидания прежние результаты остаются на месте, но добавлять устаревший результат нельзя. Проверка соответствия результата текущим тексту/магазину/настройке просмотра остаётся. Индикатор больше не вставляет отдельную строку в форму, а isNewProduct не сбрасывается на каждой букве. Статус «В списке» по-прежнему строится из фактических покупок.

## Оформление магазина

В карточке рядом с названием —значок палитры. ShopAppearanceEditor объединяет подложку, фон карточек, значок и логотип. Сверху общий ShopBlockPreview; тело прокручивается, «Отмена»/«Применить» вынесены вниз. Цвета выбираются прежним общим AppearanceSheet с полем цвета/HEX, без второго собственного механизма цвета.

Изменения модального окна локальны до «Применить». Отмена возвращает исходный вид. Применение меняет черновик карточки; в базу по-прежнему записывает «Сохранить» карточки магазина. Логотип импортируется прежним PhotoStore, исходный внешний URI не сохраняется. Во время импорта закрытие/подтверждение и конкурирующие импорты блокируются. Значок и логотип взаимно исключаются.

## Группы магазина и сети

Редактор точки больше не содержит собственного порядка отделов. Главная, содержимое магазина и виджет используют ShopDepartmentEntity.displayOrder. Исторические branch_department_order сохраняются в базе и полном ZIP для чтения/повторного экспорта, но не переопределяют отображение. Старые группы по отдельным точкам продолжают читаться по прежнему контракту совместимости; новых UI-команд для них нет.

Один профиль магазина уже разделяет размещения отделов между всеми физическими точками. Если несколько профилей объединены одним networkId, synchronizeNetworkDepartments согласует состав и порядок в той же транзакции записи каталога. Текущий профиль задаёт порядок; существующие дополнительные группы сети добавляются в конец и сохраняются. Явно удалённая группа удаляется из всех профилей этой сети. Существующие placement ID и ссылки товаров для оставшихся групп сохраняются. Другие сети, отдельные магазины и принадлежность точек к ТЦ не меняются.

Согласование вызывается при сохранении карточки, изменении/удалении отдела и создании отдела из карточки товара. Импорт полной копии по-прежнему восстанавливает точный снимок; не расширяет его побочными вызовами DAO. Прежние ZIP не переписываются и не объединяются автоматически.

Порядок отделов при обходе магазина —displayOrder размещений, а не favoriteOrder общего справочника. Избранность и алфавит выпадающих списков не менялись.
