### Дополнительный дефект, обнаруженный UI-проверкой

В исходном EditEntryDialog неограниченная intrinsic-ширина нескольких текстовых полей вызывала непрерывный пересчёт layout. Snapshot-наблюдение показало постоянную смену TextLayoutResultProxy, тест не мог дождаться стабильного UI 60 секунд на API 28 и 35. Контрольный одиночный Material3 Dialog работал.

Исправление: явная ширина содержимого по доступной ширине экрана (максимум 560dp), `usePlatformDefaultWidth=false`, прокручиваемое тело, единица внутри поля количества. После исправления тот же расширенный сценарий проходит на обоих API, ручное отключение часов/ослабление таймаута теста не применяется. Скриншот `07-edit-dialog.png` просмотрен. Не приписывать прежние подвисания на телефоне именно этому дефекту без аппаратного измерения.

## Покрытие первоначального аудита

- A01/A02: ZIP v4 восстанавливает снимок целиком; JSON v1–3 сливает каталог, remap ID и stableId сохраняют текущие покупки.

- A05: общий нормализованный fuzzy ranking в пользовательских путях.

- A07: единая бизнес-команда для всех мест добавления, города, AUTO/NONE/EXPLICIT.
- A08: транзакционные количества, защита сохранений, атомарная срочность и группы операций.
- A09: уникальный индекс пары товар/магазин, проверка владельца отдела и ремонт миграцией.
- A10: очистка сирот разовых товаров и явное продвижение в каталог.
